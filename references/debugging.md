# Failures and evidence

Prerequisites: Node.js 20+, a locally installed Codex CLI, an authenticated Codex session, `gpt-6-luna` availability, and the `image_generation` feature. The runner uses only Node built-ins and does not load API credentials or SDKs. `--codex <executable>` selects an actual executable, not a shell command or `.cmd` script. On Windows use `codex.exe`.

Run `node scripts/run.mjs --probe --root <absolute-project-path>` after installation or when capability is uncertain. The probe asks the relay whether the tool is exposed; it does not invoke image generation. A successful probe is not proof that a subsequent generation will succeed or that 16 simultaneous requests are accepted. A real smoke generation is the stronger check.

Each actual generation needs a zero process exit code and a real PNG created during the attempt. Evidence is either a completed image tool event plus the model's generated path, or a new PNG in `$CODEX_HOME/generated_images/<worker-thread-id>/` tied to the CLI's `thread.started` event. Some CLI versions save real images there while hiding tool events and returning no file path to the relay; their model may incorrectly report unavailable. The runner recovers that exact thread's artifact and records the original model report and evidence type. It never scans unrelated threads or trusts model assertions alone. Multiple thread outputs are rejected because one generation was requested. Source references cannot masquerade as generated output. PNG signature, chunk checksums, structure, dimensions, and decompressible image data are checked; an output hash is saved after copying.

Explicit image-tool cancellation, abortion, error flags, or unsuccessful results always fail, even when a thread PNG exists. A tool event used as success evidence must report completion/success. PNG validation checks legal IHDR color/depth/method values, exact decompressed scanline length, and each row's filter byte. Adam7 interlaced and indexed-color PNGs are explicitly unsupported and rejected. Noninterlaced grayscale, grayscale with alpha, RGB, and RGBA PNGs are supported.

Read the job's attempt event/stderr logs and receipt for the actual error. Unavailable tools, invalid output, missing evidence, and process failures produce failed/unavailable statuses and a nonzero batch exit. Other jobs can finish independently. Fix the underlying issue then run the same jobs file again; successful matching jobs are skipped only after their PNG hash is rechecked. The runner does not retry, fall back to another model/API, or publish outputs.

Generation workers are instructed to use the built-in tool once and return its file path. A role marker and environment flag prevent routing back into this skill. The CLI uses a workspace-write sandbox rooted in the individual attempt directory, not the project root; workers must not run commands or edit files. Tool availability and event formats may vary by CLI version; do not relax evidence checks to hide a compatibility failure. Share redacted logs when diagnosing publicly.
